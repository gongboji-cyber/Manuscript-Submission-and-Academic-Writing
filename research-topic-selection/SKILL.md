# 科研选题与立项审计

目标不是制造“看起来创新”的题目，而是在昂贵实验、模型开发或写稿前，找出**重要、尚未解决、可严格检验、值得投入**的问题。默认中文讨论；英文研究问题、标题和投稿定位可按需生成。可以推荐停止：停止是有证据的资源配置决定，不是执行失败。

## 先选工作模式

1. **机会扫描：** 给定领域/资源约束，生成少量可比较候选，先浅筛后深审；不把“某论文未来工作”自动当作空白。
2. **单题压力测试：** 用户已有假说、数据或模型，识别最接近前作、最强替代解释、最短否证路径。
3. **拒稿/阴性结果复盘：** 区分创新性、设计有效性、独立证据、代码/报告、期刊契合；只在可以增加可检验证据时推荐继续。
4. **选题组合排序：** 比较候选的科学价值、增量、数据关口、失败成本与可执行性；先剔除硬门槛不合格者，评分只作讨论辅助，不产生伪精确综合分或录用概率。

## 工作流：先判值得做，再判怎么做

1. **建立选题卡。** 明确问题、受益对象/决策场景、主张类型（描述现象、机制、方法学、决策改进）、能推翻主张的观察、领域与可用时间/算力/预算/伦理限制。记录数据与文献的当前状态：`VERIFIED`、`PARTIAL`、`UNVERIFIED`、`NOT_RUN`，不得以计划代替结果。使用 [选题档案模板](assets/topic-dossier-template.md)。
2. **开展对抗式新颖性审计。** 搜“最相似结论/实验/方法”而不仅是相同关键词，追踪关键原论文、后来比较、反证、预印本、代码和基准版本。做“前作已经证明什么 → 本题多证明什么 → 这一增量为何重要”的对照；分别检查**新场景、新证据、新方法、新决策价值**，不能互相冒充。新颖性检索范围有限时只能说“在已检索范围尚未找到”，不得宣称“首次”。遵循 [问题价值与新颖性](references/novelty-and-problem-choice.md)。
3. **设置真实数据关口。** 核验每个候选数据集的可访问性、文件大小/格式、元数据、许可、去重与来源谱系、目标对象覆盖、标签或参考标准如何建立、训练/调参与外部验证的独立程度。**下载 403/大文件/缺少处理表是访问或工程障碍，不等于科学上无数据；数据公开、数据集名字不同也不等于独立。** 无有效参考标准不允许以内部指标冒充外部实验验证。先做目录/样例/元数据小审计，再有界尝试取数；关口不通过不启动大实验。遵循 [可行性与裁决关口](references/feasibility-and-decision-gates.md)。
4. **冻结可证伪的最小研究设计。** 写下主要 estimand/结局、实验或统计独立单位、最小有意义效果、最强朴素基线、最危险泄漏路径、替代解释、预定失败信号、精度/不确定性方案和公平预算。比较不同模型时固定可比任务与资源；考虑随机/频率/文献先验、任务常识基线及必要消融。明确“若结果 A/B/C，则各自能得出什么结论”，**阴性结果的价值依赖检验强度和精度，不保证可以发表**。需要统计细节时转 `guide-research-methods-statistics`。
5. **只运行最短区分性试点。** 先冻结选样、阈值、候选排序、预算、纳排与分析脚本；不根据看到的效果更换主张。核查输入版本、哈希、失败原因和有效样本量；区分探索、事后分析和真正独立验证。试点应能在两个竞争解释中作出区分，否则继续压缩或停止。数据不合格时只输出 `NOT_RUN`，不能制造结果或用内部数据替代。
6. **做单一证据裁决。** 逐关口列出通过/未通过/未知、阻断证据、最小解锁条件、上限投入（时间/算力/下载量）、复核日期、潜在论文贡献及最强审稿人/编辑反对意见。使用下方唯一状态；**不要**把缺证据默认为否定事实，也不要为已投入成本追加研究。只有通过科学关口再评估期刊范围、开源代码、复现包、费用与投稿政策。

## 裁决词典（每次交付仅一个主裁决）

| 主裁决 | 条件与下一步 |
| --- | --- |
| `EXPLORE_ONLY` | 问题未清或新颖性尚未核查；只允许限额检索与访谈，不准大规模计算 |
| `HOLD_NEED_EVIDENCE` | 缺独立参考标准、覆盖量或关键机制证据；明确解锁所需材料 |
| `HOLD_DATA_ACCESS` | 科学上有潜力，但本环境无法取得或解析数据；把访问失败与数据不合格分开 |
| `GO_MINIMAL_PILOT` | 重要性、新颖性假说、可用数据和公平设计初步成立；先做冻结试点 |
| `GO_FULL_STUDY` | 预定义试点与科学/资源关口均通过；列明仍未证明的部分 |
| `STOP` | 贡献被充分覆盖、不可修复偏倚、无可识别结论，或成本远超合理价值；说明再启动条件（如有） |

状态反映**当前证据下的行动建议**，不等于科学命题真假、数据仓库“资格”的绝对结论，也不是期刊接收率。可附 `data_gate=ACCESS_BLOCKED / INELIGIBLE / ELIGIBLE / UNKNOWN` 和 `pilot=NOT_RUN / RUN / INVALID`，但只给一个主裁决。

## 来自既往研究复盘的反例清单

- **“相似模型分数但结构不同”** 之类现象，即使稳健，也可能早已成立；若主张实验决策价值，就需要独立扰动/前瞻验证及实际候选覆盖，而非再画一组网络差异图。
- **金标准参与输入构造**（例如由真值掩膜导出测试提示）可能形成 oracle 优势；首先审计信息路径，再谈模型胜负。
- **化学结构/对象身份重复或近邻** 可令随机切分夸大泛化；独立单位、同源分组及强朴素基线应早于算法创新叙事。
- **运营标签或既有基准标签** 不自动成为独立实验真值；源数据重分析不自动变成新生物学发现。
- **复现实验“环境修好才有结果”** 必须设置工程止损时间；不可复现也要区分源码缺失、依赖失效和科学反证。
- **拒稿后的修补**：报告性错误/代码未随稿提交应修，但不会自动治愈创新性不足；应先检验是否能新增值得发表的证据。

这些是一般化的失败模式，不泄露任何尚未公开项目细节；不同课题须重新找原始证据。详见 [经验→可执行关口](references/feasibility-and-decision-gates.md)。

## 联动与交付

文献检索与逐主张核验转 `retrieve-and-match-references`；核心前作深入审读转 `critically-read-literature`；estimand、重抽样、分层或聚类、泄漏与统计设计转 `guide-research-methods-statistics`；通过立项关口后才转 `audit-and-polish-manuscript`、`write-manuscript-supplement` 等投稿模块。不要因技能互相调用而把文献阅读、验证或实验标为“已完成”。外部借鉴和原创改写见 [来源与改造说明](references/sources-and-adaptations.md)。

默认交付：一页问题/增量陈述、最近邻前作对照、证据与来源台账、数据资格矩阵、竞争解释与结果树、冻结试点计划、预算/停止规则、最强 desk-reject 理由，以及**带解锁条件的唯一主裁决**。仅有想法时交付计划，不虚构证据或可用数据。
