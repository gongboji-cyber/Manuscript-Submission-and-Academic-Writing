# Round 7：Word任务执行层最小资源包

## 本轮问题与完成条件

Round 6确认：单表任务即使经过三次提示词修订，执行者仍会读取完整20项清单。问题不再是措辞不够强，而是完整技能目录仍对局部执行者可见，缺少可审计的执行层资源边界。

本轮在任何候选修改前冻结11项条件：分包必须确定、可复现、无未知依赖；局部包物理排除清单，完整审计包保留清单；错误scope、缺失源和非空输出安全失败；正常、复杂合并边界、完整审计反向例和不适用例均需通过；所有DOCX输出必须做结构与真实页面验收；最后由隔离评分者逐项复核。

## 最小改动

只改Word模块的3处运行文件：

1. 新增 `scripts/stage_task_bundle.py`。它仅用Python标准库，从同一Word技能源生成 `local-three-line` 或 `full-audit` 白名单包，在包外写入含来源路径、字节数和SHA-256的稳定清单；输出路径已存在、scope未知或源缺失时停止，不覆盖或删除用户文件。
2. Word入口要求向独立执行者/子agent交接前先分包；范围变化时重新分包，不能在局部包内凭记忆重建缺失清单。
3. 三线表参考将“F20”改为不依赖清单编号的视觉验收表述，避免局部包残留完整审计编号。

第一次局部运行还暴露出导入辅助函数会在包内生成 `__pycache__`，使运行后的目录多出未列入清单的文件。候选因此增加 `python -B`/禁用字节码要求，并只重跑受影响的正常例；新版资源包未再产生缓存。这个失败保留为回归依据，没有通过忽略缓存来放宽清单完整性。

## 分包与机械测试

- 两次独立生成的局部包清单逐字节相同，SHA-256均为 `8a8088fc…32d`。
- 局部包只含局部入口、格式规则、三线表参考和辅助函数；全文搜索无 `checklist.md`、F01或F20。完整审计包包含 `references/checklist.md`。
- AST导入审计只发现 `argparse/hashlib/json/os/pathlib/shutil/tempfile`；未安装依赖。
- scope未知、源目录缺失、输出目录非空三例均非零退出；非空目录中的sentinel原样保留。
- skill-creator `quick_validate.py` 对修改后的Word技能返回 `Skill is valid!`。

## 盲测结果

执行者只收到原始请求、合成DOCX、分配的快照/包和空输出目录，不收到量表。读取记录是执行者声明，不是操作系统级追踪。

## 独立复核与测量边界

隔离评分者只读取冻结量表、原始请求、日志、输出、父级技术记录和页面图；未读取技能实现、仓库或作者结论。最终为 **11 met / 0 not met / 0 unclear**。标准库与逐文件清单两项由父级AST审计和逐项哈希记录提供证据，评分者仍保留“未直接查看实现/包内容”的边界。

本轮不证明一般成功率、科学正确性、期刊合规或效率提升。full snapshot的旧缺陷只运行一次且未复现，因此不能声称相对当前全快照的成功率改善；可以确认的是局部包从机制上不含完整清单和其他模块。模型ID、token、费用和可比耗时未提供，不能据文件数或日志长度声称成本下降。DOCX均为单页公开合成材料，尚未覆盖跨页长表；LibreOffice页面一致也不保证所有Microsoft Word版本一致。
