# T01-topic-triage

当前唯一主裁决：`EXPLORE_ONLY`。三项想法都还缺最近邻前作、标签来源和外部验证独立性的核查，因此现在不能选出“最佳题目”，也不能进入大规模计算。附加状态：`data_gate=UNKNOWN`，`pilot=NOT_RUN`。这只是当前行动裁决，不表示三个想法无价值。

先做一轮有上限的立项审计，每个想法建立同样的一页选题卡：

1. 把主张写成一句可证伪问题：目标人群/样本、拟比较条件、结局、时间点、预期新增知识，以及什么观察会推翻它。另写“结果为零或反向时还能得到什么有信息量的结论”。
2. 做对抗式最近邻核查。检索同一科学命题、最相似数据—方法—结论组合及反向证据，而不只搜相同关键词；记录数据库、查询、日期、阅读范围和来源版本。对每个候选形成“前作已证明什么—本题多证明什么—这一增量为何重要”的对照。在实际检索完成前，不使用“首次”“尚无研究”等表述。
3. 审计数据资格，而不仅是可下载性。逐数据集核对许可、版本、样本与患者对应、重复/共享队列、批次、标签由谁以何种规则生成、标签是否参与输入构造，以及拟用外部验证集与开发数据是否在人、中心、项目或来源谱系上真正独立。公开、不同名称或不同 accession 都不自动等于独立证据。
4. 只有 G0 问题价值、G1 最近邻增量、G2 数据/真值和 G3 公平可识别设计至少取得足以支持试点的证据后，才冻结最小试点：独立单位、estimand/主结局、最强朴素基线、泄漏检查、最小有意义差异或精度目标、候选范围、预算、失败信号和结果树。试点未运行前保持 `NOT_RUN`。

三题的比较不做伪精确总分；先淘汰硬门槛失败者，再按“重要性、可证实增量、标签/参考标准可信度、外部证据独立性、可证伪性、最小试点成本、阴性结果信息量”分别标记强/中/弱/未知并附依据。

暂时不要启动：全量下载与预处理、模型开发/调参、成批差异分析或生存模型、事后挑终点、把内部切分称为外部验证、论文写作与图表美化，以及以公开数据或标签可用性替代科学适格性。也不要为了三个题都“有结果”而同时开跑。

解除当前裁决的条件如下：

- 若最近邻已完整覆盖拟议主张且没有新的独立证据价值，或标签—输入存在不可拆的循环，转 `STOP`。
- 若问题仍有价值，但缺可接受的独立标签/参考标准或外部验证，转 `HOLD_NEED_EVIDENCE`，并写明所需数据、覆盖和验证设计。
- 若科学上可能合格、仅因当前无法取得或解析数据而受阻，转 `HOLD_DATA_ACCESS`，不得说成“数据不存在”。
- 只有增量假说、数据资格与公平设计有初步证据，且冻结试点能区分竞争解释时，才转 `GO_MINIMAL_PILOT`；预定义试点和资源关口实际通过后，才可能转 `GO_FULL_STUDY`。

本次可交付的是三份空白选题卡、最近邻检索方案、数据资格核查表、候选比较框架和裁决门槛；没有检索或试验结果可报告。

# T02-approved-sap

本次直接进入正式 SAP 交接，不重新做选题、创新性或数据许可审计。团队已经书面确认的研究问题、许可、最近邻工作和独立验证集应作为带版本的上游依据引用，而不是再次开启裁决。当前可交付为“可签审的 SAP 骨架”；因为尚未给出具体人群、暴露/干预、结局和数据层级，以下字段必须由现有批准材料填入，不能代填。

## 1. 冻结信息

- 项目、SAP 版本、UTC 日期、批准方案/数据字典/许可文件的版本或哈希、独立验证集身份与确认记录。
- 明确 SAP 时点：事前，还是已经看过任何结局/模型结果后追溯制定。若结果已知，必须标为追溯性，并列出已知内容。
- 指定冻结日期、批准角色、允许修改的条件，以及所有偏离记录的位置。

## 2. Estimand

用一个完整句子冻结主 estimand：

> 在【目标人群】和【时间零点/窗口】内，比较【A 与 B，或暴露水平/预测策略】，估计【明确定义结局】的【风险差、均值差、比值、时间结局或预定性能汇总量】，以【患者/中心/其他独立单位及其权重】为目标。

同时分开记录：目标人群、处理/暴露或比较条件、结局变量、时间点/随访窗、总体汇总尺度和方向。若是试验，再明确中间事件策略；若是观察性因果问题，列出目标试验与识别假设；若是预测/诊断研究，定义预测时点、参考标准、阈值策略和评价总体。`estimand`、`estimator` 与最终 `estimate` 必须分列。

## 3. 独立单位与信息结构

独立单位由数据生成过程决定，不能默认等于数据表的一行。SAP 必须列出：

- 行单位与最高可辩护独立单位（如患者、中心、批次或研究）；
- 同一患者的多样本/多时间点、患者嵌套中心、配对或交叉依赖；
- 患者等权、样本等权或其他目标权重，以及为什么它对应 estimand；
- 去重键、分组切分、训练—调参—验证隔离和任何共享来源谱系；
- 有效独立单位数、事件数/cluster 数及其对精度或样本量的约束。

若独立单位或泄漏路径仍无法由批准材料识别，这是 SAP 签署前的阻断项，而不是通过选用更复杂模型补救。

## 4. 主分析 A01

A01 必须预先唯一指定：分析总体与纳排/分母、目标量、效应尺度、估计方法、调整变量及其领域理由、函数形式、依赖结构处理、缺失数据主策略、多重性族、区间类型与置信水平、诊断、失败处理和结论边界。方法随已批准问题选择：连续、二分类、率、生存、重复/聚类、诊断或预测结局不能互换估计目标。

主分析至少承诺：

- 报告效应量与区间，而非只报告 P 值；
- 保留预先定义的配对/聚类结构和完整分析分母；
- 不按单变量 P 值筛混杂因素，不按正态性检验结果自动更换目标量，也不在看结果后挑主模型或阈值；
- 预先定义模型不收敛、分离、极端权重、支持域不足或验证泄漏时的失败信号与处置；
- 计算研究还要冻结候选空间、信息与算力预算、基线及全流程折内拟合。

## 5. 敏感性与补充分析

敏感性分析要围绕最可能改变主 estimand 估计的假设预先设置，而不是罗列“换几个模型”：

- S01：同一 estimand 下改变对相关/聚类结构的合理处理或权重，检查独立单位假设；
- S02：同一 estimand 下评估缺失机制与处理，例如主 MAR 假设之外的预定 MNAR 情景；
- S03：预定的测量误差、标签/参考标准争议或纳排边界分析；
- S04：功能形式、极端值/影响点和模型规格的合理替代，保留同一目标量；
- S05：开发—验证完全隔离、重复/同源样本排除或中心/时间外推的压力测试；
- S06：多重性、阈值或最小有意义差异相关的预定稳健性检查。

回答不同问题或改变总体、结局、权重、时间窗的分析应列为“补充分析”，不得伪装为同一 estimand 的敏感性分析。每项都写出进入条件、失败信号、解释分支和是否影响主结论。

交接完成条件：上述字段能从批准材料和数据字典中定位，A01 与每个敏感性分析均有分析 ID，代码/环境/随机种子/输入输出哈希与偏离登记位置已指定，并由统计负责人和课题负责人签审。数据未实际运行，因此本次不提供数值结果，也不声称 SAP 已执行。

# T03-rejection-reframe

当前唯一主裁决：`EXPLORE_ONLY`。现有材料只能证明编辑/审稿流程提出了“创新性不足、独立证据不足”这两个拒稿理由，不能证明这些判断必然正确，也不能证明稿件值得重做。此时继续补代码和全文润色都不是主路径；先判断是否存在可发表的新增、可独立检验的科学贡献。

建议按以下顺序推进：

| 阶段 | 首选模块与当前任务 | 进入条件 | 停止/转向条件 | 当前允许交付 |
|---|---|---|---|---|
| 0. 拒稿事实拆解 | 科研任务总控：把每条拒稿意见映射到具体主张、材料位置和所缺证据 | 有决定信、评审意见和当前稿件版本 | 不能定位意见所指主张时先补材料，不推测审稿人意图 | 拒稿问题—主张—证据缺口表 |
| 1. 原创性与重做价值 | `research-topic-selection`：对抗式最近邻审计，区分“已有工作已回答”与“仍有重要、可证伪的增量” | 已写出候选新主张和失败条件 | 最近邻已覆盖全部主张且无新增独立证据价值，则 `STOP`；检索不足则保持 `EXPLORE_ONLY` | 选题卡、检索方案、最近邻对照、最强 desk-reject 理由 |
| 2. 核心前作与批评复核 | `retrieve-and-match-references` + 必要时 `critically-read-literature`：核对来源身份、阅读范围、正反证据及拒稿意见的最强替代解释 | 找到真实候选来源并可读到支持判断的部分 | 只有摘要/片段或来源冲突时不得宣称创新性已证实；记录未知 | 来源台账、主张—证据图、条件性判断 |
| 3. 独立证据与数据关口 | 选题模块先审计标签/真值、样本谱系、验证集独立性、覆盖和泄漏 | 增量假说仍成立，且存在可核查数据/验证路径 | 无独立参考标准、不可修复泄漏或目标量不可识别时 `HOLD_NEED_EVIDENCE` 或 `STOP`；单纯访问受阻则 `HOLD_DATA_ACCESS` | 数据资格矩阵、信息流图、解锁材料清单 |
| 4. 冻结最小区分性试点 | `guide-research-methods-statistics`：冻结 estimand、独立单位、强基线、精度、预算、失败信号和结果树 | G0–G3 有初步依据，且试点可区分“真实新增价值”与替代解释 | 试点不能区分解释、无有效验证单位或预算不合理则不运行/停止；未运行保持 `NOT_RUN` | 带版本的试点方案与 SAP 草案，不含虚构结果 |
| 5. 实施与升级裁决 | 仅在授权、数据合格且方案冻结后运行最小试点 | `GO_MINIMAL_PILOT` | 泄漏/无效验证使试点无效；区间过宽则信息不足；只有实际通过关口才考虑 `GO_FULL_STUDY` | 实际运行记录、效应与区间、偏离和新裁决 |
| 6. 稿件与代码交付 | `audit-and-polish-manuscript`：证据一致性、报告、代码说明与语言；必要时补充材料 | 新贡献和独立证据路线已经通过，或团队明确只修复可复现性/归档问题 | 若核心创新性/证据缺口未解，不把语言和开源修补写成已解决 | 修订稿、代码/复现说明、变更记录；不自动投稿 |

当前可以做并交付：拒稿证据拆解、有限的最近邻检索计划、数据与独立验证资格清单、竞争解释、冻结试点草案和带解锁条件的裁决。当前不应启动：无边界地补代码、重新调参或增加探索性图表，全文润色/重写，声称“首次”，把内部重采样包装为独立验证，或承诺投稿。

后续裁决是可解除的：最近邻和数据关口初步通过且最小试点能区分关键解释时，升级为 `GO_MINIMAL_PILOT`；创新性尚有可能但缺独立真值时转 `HOLD_NEED_EVIDENCE`；仅访问受阻时转 `HOLD_DATA_ACCESS`；若现有工作已覆盖贡献，或偏倚/泄漏不可修复且没有新证据设计，则 `STOP`。没有新实验的当前状态下，不能升级为原创研究已可行。
