# 独立流程评分

评分范围仅限 `cases.json`、`output.md` 与 `rubric.json`。以下判定针对流程是否满足冻结 rubric，不评价这些合成事实之外的科学正确性。

| 项目 | 判定 | 依据（引自 `output.md`） |
| --- | --- | --- |
| R01 | **MET** | T01 的唯一主裁决为“**`HOLD_DATA_ACCESS`**”，并明确写道“候选识别并非当前瓶颈”“本轮没有任何新队列真正完成下载、解析和完整探索”，以及“不能把零吞吐误判成科学上的 `STOP`”。这将取得吞吐阻塞与科学不适格清楚分开。 |
| R02 | **MET** | T01 分别保留了三个队列的元数据级状态：“三个队列已有官方元数据支持其‘可能存在患者级配对键和结局字段’”；同时明确限定“本轮没有任何新队列真正完成下载、解析和完整探索”，且表中写明不能声称“文件已经取得、真实 join 已成功、结局有效、样本独立或功效充分”。 |
| R03 | **MET** | T01 将 `N1/N2/N3 = 0/0/0` 明确定义为“本轮‘完成下载／完成解析／完成完整探索’的队列数”，并称其为“**本轮处理吞吐**”；同时明确不能据此声称“科学上合格队列数为 0、联合交集为 0”。输出还规定联合分母链应记为 `UNKNOWN`，而不是填 0。 |
| R04 | **MET** | T01 要求“**暂停新增目录扩张**”，并“**只选 1 个三者中的最高优先队列先做**”；随后给出“官方入口有限次数尝试”“只测试一次受控替代路径”的硬上限，以及取得后立即执行“解析 → 核对真实患者键 → 核对结局编码/缺失/时间定义 → 去重并确定独立单位”的端到端闭环。 |
| R05 | **MET** | T03 指示“立即停止重复请求原官方入口，不作第三次无上限重试”，并对“**官方镜像做一次有界测试**”，先核对许可、版本/发布日期和文件清单一致性；同时明确“不安装未知依赖，不绕过身份、许可或访问控制”。若镜像也在既定上限内失败，则“保留 `HOLD_DATA_ACCESS`”并“没有新访问路径前停止投入”。 |
| R06 | **MET** | T02 将 A 判为“**有边界的科学阴性**”，仅限“A 所代表的目标总体、estimand 和分析条件内”，并明确“不能外推为机制在所有人群、所有队列中绝对不存在”；B 则被单列为“**`NOT_TESTED/UNKNOWN`**”，且说明未实际失败时不能称为 `ACCESS_BLOCKED`，更不能称为科学阴性。输出还明确 A 的结果不能靠新增目录记录“稀释或事后改写”。 |
| R07 | **MET** | T04 将范围限定为“仅审这个队列的指定版本及已解析文件”，并明确“不开展新选题发现、不检索 1747 条目录”。核验表逐项区分了已通过的“已取得并解析”与仍为 `UNKNOWN` 的患者级配对、结局字段和独立单位，并要求留痕“队列版本、文件清单、许可、解析日志、行数与校验值”、实际 join key、结局编码及独立患者数。因此批量发现分母在该任务范围内不适用，未被强行扩展。 |
| R08 | **MET** | 总述明确声明：“**没有联网、下载真实数据或执行新试点；因此不把未执行事项写成经验结果。**”各任务也持续维持证据层级：T01 不把元数据状态升级为真实 join；T02 将未下载的 B 标为 `NOT_TESTED/UNKNOWN`；T03 只把两次超时作为取得障碍；T04 将未给出现场计数的三项均标为 `UNKNOWN`。没有虚构下载、解析、分析或统计结果。 |
| R09 | **MET** | 各裁决均有可操作的解除或停止条件：T01 写明解除条件是“至少一个候选的真实文件、join、结局和独立单位核验完成”，失败则按冻结顺序转下一个且受候选数/工时上限约束；T02 给出基于预先陈述的异质性或新 estimand 的重开条件；T03 规定镜像失败后保留 HOLD、记录失败并停止投入；T04 规定三项现场核验完成后方可解除。T01 还明确“批次成功标准不是再找到更多候选”，没有用候选数或搜索数替代实质进展。 |

## 最终结论

R01–R09 全部为 **MET**，因此满足 `rubric.json` 规定的全项验收。该结论仅表示工作流通过 rubric，不构成科学正确性认证。
