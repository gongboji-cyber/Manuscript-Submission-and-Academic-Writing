# 四个科研选题请求的执行答复

以下裁决仅依据题面给出的合成事实。没有联网、下载真实数据或执行新试点；因此不把未执行事项写成经验结果。

## T01｜1747 条目录记录、6 个冻结候选，但本轮取得吞吐为 0

### 唯一主裁决

**`HOLD_DATA_ACCESS`**。

理由是：候选识别并非当前瓶颈；三个队列已有官方元数据支持其“可能存在患者级配对键和结局字段”，但本轮没有任何新队列真正完成下载、解析和完整探索。因而 G3 的实际访问、真实联结、有效标签、独立单位和最终可分析交集仍未通过。现在既不能升级为 `GO_MINIMAL_PILOT`，也不能把零吞吐误判成科学上的 `STOP`。

### 计数应如何解释

| 数字 | 正确含义 | 不能据此声称 |
| --- | --- | --- |
| 1747 | 本轮检查的目录记录数，是发现漏斗的 L0 分母 | 1747 个独立课题、1747 个合格队列，或 1747 个完成深审的数据资源 |
| 6 | 已冻结、等待后续核验的候选数 | 6 个 G0–G4 全 PASS 的题目 |
| 3（GSE134544、GSE73661、GSE191328） | 官方元数据层面核验到患者级配对与结局字段的候选数 | 文件已经取得、真实 join 已成功、结局有效、样本独立或功效充分 |
| N1/N2/N3 = 0/0/0 | 若 N1、N2、N3 分别定义为本轮“完成下载／完成解析／完成完整探索”的队列数，则它们是**本轮处理吞吐** | 科学上合格队列数为 0、联合交集为 0，或三个队列均不适格 |

联合数据分母仍应记录为：`N0 → N_key → N_label → N_independent → N_eval = UNKNOWN`，而不是填 0。只有文件取得后按冻结 join 规则核实严格为零，才可把相应节点写成 0。

### 下一批资源的最小动作

1. **暂停新增目录扩张。** 将下一小批资源从“继续识别候选”转到“完成一条端到端取得链路”。
2. **只选 1 个三者中的最高优先队列先做。** 用预先冻结的决策价值、文件规模、格式可解析性和许可风险排序；题面不足以武断指定某个 GSE 编号。
3. **给取得动作设硬上限。** 例如官方入口有限次数尝试；如有官方镜像，只测试一次受控替代路径；记录 URL、版本、许可、时间、字节数、校验值与失败原因。不安装未知依赖，不绕过许可，不无限重试。
4. **一旦取得，立即完成最短闭环：** 解析 → 核对真实患者键 → 核对结局编码/缺失/时间定义 → 去重并确定独立单位 → 报告 `N0 → N_key → N_label → N_independent → N_eval`。
5. **批次成功标准不是再找到更多候选，** 而是至少让 1 个候选从元数据状态推进到“实际文件已取得且患者级资格已审计”。若该队列失败，再按冻结顺序转向下一个，最多使用事先设定的候选数或工时上限。

Gate 摘要：G3=`UNKNOWN/ACCESS_BLOCKED`（尚未完成实际取得与联结）；G4=`NOT_TESTED`；pilot=`NOT_RUN`。解除条件是至少一个候选的真实文件、join、结局和独立单位核验完成。

## T02｜队列 A 给出精确阴性，队列 B 仅有题录与摘要

### 判断

这不是目前证据下可直接称为“工程阻塞与科学阴性的混合”。更准确的拆分是：

- **队列 A 是有边界的科学阴性。** 它已按冻结方案完成，主要估计区间排除了预设最小有意义效果，且正对照有效；因此在 A 所代表的目标总体、estimand 和分析条件内，可以说“未达到预先定义的有意义效果”。不能外推为机制在所有人群、所有队列中绝对不存在。
- **队列 B 是 `NOT_TESTED/UNKNOWN`。** 只有题录和摘要、尚未下载，只能说明取得和分析没有执行；除非已有实际失败记录，否则不能称为 `ACCESS_BLOCKED`，更不能称为科学阴性。

### 唯一行动裁决

**对当前冻结主张及“继续扩大目录搜索”作 `STOP`：不再扩大目录搜索。** A 的有效精确阴性不能靠不断加入新目录记录来稀释或事后改写。B 只有在它是事先规定的外部验证、代表有科学依据的不同目标总体，且其结果会改变结论边界时，才值得安排一次有界取得与复核；这属于完成既有候选，不是继续扩目录。

重新打开条件：B 或其他队列必须有事先陈述的效应异质性依据、新的目标总体或不同但明确的 estimand，并在看结果前冻结分析。若只是希望“再找一个阳性队列”，不应重开。

## T03｜高价值队列官方入口两次超时，官方镜像未测试

### 唯一主裁决

**`HOLD_DATA_ACCESS`**。

两次超时证明的是当前官方入口的取得障碍，不证明该队列科学不适格。官方镜像是尚未测试、且可能以最低成本改变裁决的下一步。200 个容易下载但只有横断面替代结局的队列并不估计同一目标量，数量不能补偿终点价值和可识别性的下降。

### 下一步

1. 立即停止重复请求原官方入口，不作第三次无上限重试。
2. 对**官方镜像**做一次有界测试：先确认许可、版本/发布日期、文件清单与主入口一致性，再尝试取得；成功后核对大小与官方校验值（若提供），记录来源谱系。
3. 不安装未知依赖，不绕过身份、许可或访问控制；只使用已批准的标准工具和格式。
4. 若镜像成功，进入解析和患者级资格审计；若镜像也在既定时间/次数上限内失败，保留 `HOLD_DATA_ACCESS`，记录两条入口的失败证据，并通过维护方或正常授权渠道处理。没有新访问路径前停止投入。
5. 不把 200 个低价值队列当作替代。只有研究问题本身愿意改成“横断面替代结局”且重新定义 estimand、价值与最小效应时，才能作为一个新题目评估，不能称为原题的备选验证。

## T04｜只核验一个已取得并解析的队列

### 审核范围

仅审这个队列的指定版本及已解析文件，不开展新选题发现、不检索 1747 条目录，也不评价未被请求的新颖性。核验目标限定为：患者级配对、结局字段、独立单位。

### 范围合适的核验记录

| 项目 | 本题现有证据 | 必须在已解析数据中核对并留痕 | 当前状态 |
| --- | --- | --- | --- |
| 实际访问与解析 | 用户明确说明已完整获得并解析 | 队列版本、文件清单、许可、解析日志、行数与校验值 | `PASS`（限“已取得并解析”） |
| 患者级配对 | 尚未给出实际键和计数 | 患者 ID 的来源；各表 join key；键的唯一性；一人多样本/多时间点规则；缺键、重复键、冲突键；完整配对患者数 | `UNKNOWN` |
| 结局字段 | 尚未给出字段审计 | 字段名与数据字典；编码、时间起点、随访窗、删失定义；缺失率；事件/非事件数；结局是否在预测时点之后可得；与患者键联结后的有效标签数 | `UNKNOWN` |
| 独立单位 | 尚未给出来源结构 | 独立单位是否为患者；重复样本如何聚合或建模；同一患者不得跨训练/测试；站点、家庭、批次等聚类；去重后患者数与事件数 | `UNKNOWN` |

最低限度应输出一条真实分母链：

`N0（解析记录） → N_key（有合法患者键） → N_label（有合格结局） → N_independent（独立患者） → N_eval（最终纳入）`

并附上每步排除原因、重复/冲突数、缺失数和结局分布。行数、样本数或标本数不能代替独立患者数。

### 唯一主裁决

**`HOLD_NEED_EVIDENCE`**。

已取得并解析只让访问层通过；题面没有提供真实 join、标签和独立单位计数，所以不能判定 G3 PASS，也不能判为 FAIL。解除条件是上述三项现场核验全部完成，且 `N_key`、`N_label`、`N_independent` 与拟议 estimand 使用同一纳排规则。若核验通过，可将本队列的数据资格记为 `ELIGIBLE`；这仍不自动代表新颖性、功效、G4 试点或整个课题已经 GO。

## 汇总

| 请求 | 主裁决 | 关键边界 |
| --- | --- | --- |
| T01 | `HOLD_DATA_ACCESS` | 0/0/0 是取得流水线吞吐，不是科学合格交集为零 |
| T02 | `STOP` 当前主张的继续扩目录 | A 为范围内科学阴性；B 是未执行，不是已证实工程阻塞 |
| T03 | `HOLD_DATA_ACCESS` | 有界测试官方镜像；不以 200 个替代终点队列偷换问题 |
| T04 | `HOLD_NEED_EVIDENCE` | 只审单一已解析队列；访问 PASS 不等于 join、标签和独立性 PASS |
