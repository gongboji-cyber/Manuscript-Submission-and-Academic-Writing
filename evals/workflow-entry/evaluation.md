## 具体缺陷与最小改动

固定基线的104个公开文件中有十个专业模块（原八个及新增流程图、专利），没有根SKILL.md。各模块有自己的局部约束，但缺少一个统一的任务分流入口，以及跨模块材料版本与核验接续约定。观察依据是实际文件树与十个模块入口；不是声称已观察到十个模块的科学错误。

候选只增加六个运行文件：根SKILL.md、agents/openai.yaml、陌生问题协议、交接协议、轻量记录模板与来源边界。按需选模块，保持局部任务范围，区分执行/核验/新鲜度，约束结果改动后的依赖失效与重核。既有104文件逐一以Git blob SHA确认不变。没有新增临床推荐、统计阈值或法律裁决。

结构条件：十个模块入口与相关资源可解析；符合skill-creator基础格式；基线文件不变。行为条件：只做所需任务；不把报告数值当独立复算；跨版本更新后明确受影响检查的重做与独立工作的接续；引用身份和语义分开；陌生格式必须按所读说明实际验证。

## 实际观察与未通过项

结构检查通过：[static-verification.json](static-verification.json)。另一个隔离代理按冻结标准复核：[independent-review.md](independent-review.md)、[independent-assessment.json](independent-assessment.json)。两版各有10项met、1项not_met、3项unclear；这不是加权总分或科学质量认证。

- 两版均保留v2数字与不确定性，撤去无依据优势/临床获益，拒绝由关联线索推出因果和全人群外推。
- b把图和补充明确列为过期依赖，区分局部两句完成与跨材料未完成。这是可见的状态表达差异，不证明整体能力提升。
- **W02.5两版均not_met**：成果虽说明更新图后再检查，但未完整明确所有受影响核验在更新成果上重做，以及未受影响工作可继续。入口中已有相应原则，当前一次试用尚未证明能可靠落实。
- W01.2、W04.1、W04.4为unclear：局部成果、转换与复跑有证据，但原执行是否确实读取、从未额外操作及全过程输入保留，不能仅凭执行者自报日志独立确认。

主代理再次运行两份提交代码：[replay.json](replay.json)，正常与重复输入、ID、单位、NA及复跑期输入哈希均符合要求。随后在临时目录运行可携带脚本，重做两版的完整转换与各自边界检查：[portable-replay.json](portable-replay.json)。a的19项与b的22项采用不同拆分和执行层级，不能以数量比较效率或质量。所有这些技术检查均不认证v2分析或医学主张。

## 证据与复现

[run-manifest.json](run-manifest.json)记录基线、六个候选文件哈希、原始输入哈希、条件和可观测性限制。[results/a](results/a)与[results/b](results/b)保留执行者原样成果、代码、CSV、自报资源/命令日志及检查记录；日志不是完整原始工具事件导出。启动任务记录为摘要，不冒称原始对话轨迹。日志中的路径为本次合成试验的暂存与解释器位置。

从仓库根目录用现有Python标准库运行：

```bash
python -B evals/workflow-entry/replay_converters.py
```

脚本把公开夹具与代码复制到临时目录，执行正常/重复转换和边界脚本，输出实际命令/退出码/结果，随后清理临时目录；不改仓库中的原始结果，不调用模型，不安装依赖。要重做技能行为试用，须从固定基线及候选六文件分别建立隔离环境，只交materials原始请求与目录权限，评分资料与运行上下文分开；不能把当前已公开评分例当作新的未见任务。

流程设计参考：[OpenAI官方技能评测文章](https://developers.openai.com/blog/eval-skills)，2026-01-22，实际读取成功条件、触发/环境、任务集、轨迹与回归部分；具体适用范围及重查触发见[入口来源记录](../../references/workflow-sources.md)。本轮没有复用或安装未知GitHub依赖，也没有将skill断言当医学证据。
