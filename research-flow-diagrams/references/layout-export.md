# 布局、可编辑性与导出

## 两次冻结

**语义冻结**：确定节点、边、角色、分组、证据；可用Mermaid文本评审。**布局冻结**：在draw.io或同源代码中安排尺寸、避让和导出。不要在结构仍不断变化时为每根箭头耗时微调，也不要在已排好版后无提示地重新自动布局。

## 起始排版建议（不是期刊要求）

- 单列/双列物理尺寸依据目标期刊和投稿阶段确认；未指定时先用可打印的16:9或约180mm横版母图测试可读性。
- 字体Arial、Helvetica或支持中文的清晰无衬线，正文起点8–9 pt；真实最小字号按目标期刊、导出比例调整。不靠持续缩字号塞信息。
- 节点之间保留呼吸空间，按阅读方向排序；箭头尽量直角/短路径，同类边样式统一。跨过框体的箭头需要避让，交叉不可避免时明确分层。
- 色彩建议：背景白，主要文字深灰，流程节点浅灰/蓝，关键方法一个强调色，风险一处红橙；若色盲或灰阶下丢失含义，改线型/标签。
- 决策菱形只装短问题；从菱形出去的“是/否”要贴近相应连接且无二义性。反馈路径区分新数据和重复使用同一数据。
- 结构密度高时优先拆分为总览+局部而非随意删除必要实验步骤。

## 可编辑母版优先

| 格式 | 是否可直接单元素修改 | 用途 |
| --- | --- | --- |
| `.mmd` / `.dot` / `.json` | 改代码后重新生成 | 语义/可重现结构 |
| `.drawio` | 是（原生节点、连线时） | 布局与审稿修订 |
| `.svg` | 视元素结构与编辑软件而定 | 矢量预览与后期精修 |
| `.pdf` | 视生成路径而定 | 投稿与印刷型矢量 |
| `.png` / `.tiff` | 否（像素图） | 预览、期刊要求位图 |
| `.pptx` | 仅当使用原生形状 | 教学/答辩/用户要求逐框编辑 |

draw.io从Mermaid导入时选择 **Diagram** 而不是 **Image** 才产生可编辑图形；重新根据源生成可能覆盖人工坐标和连线路由。编辑完成后务必保存最终draw.io文件，不让旧Mermaid当唯一“最终版”。

## 验收必须查看实际文件

1. 打开最终SVG/PDF和位图预览，按100%视图检查整体层级，再放大查看所有小字、箭头端点、数学符号。
2. 文字是否溢出、中文缺字、单位截断、公式变形、转义符残留、图注与主文不一致。
3. 框体/分组是否相撞；连接是否压到文字、穿过其它节点或造成错误路径；图例是否遮挡。
4. 打印尺寸是否可读，灰阶仍能分辨；色差与对比度不能代替图例。
5. 另开draw.io源文件，确认关键形状/箭头能独立拖动；SVG嵌入组 ≠ 原生形状。
6. 核验导出的尺寸、格式、分辨率和字体；PDF是否保留文本/线条矢量。TIFF若按800dpi母版生成要用真实渲染而非低清放大。
7. 对后续每次修改重新运行代码和视觉检查；旧截图的PASS不能继承。

## 故障处理

- Mermaid节点拥挤：减少单节点文字、拆分子图、更换LR/TB、调整渲染器或用draw.io最终排版；不强行在Mermaid堆大量不可移植样式。
- 箭头“从哪里来”不清楚：明确源与目标端口、用中继节点/短标签；不通过藏箭头解决。
- SVG→PDF字体替换：保留字体说明、嵌入/检查PDF字体，优先文稿内原生渲染器；不可仅看文件后缀断言纯矢量。
- draw.io无法打开：核查mxfile/mxGraphModel、节点ID、端点和XML转义；重新导入实际GUI。
- AI位图错误：回到可编辑语义源改，不能用图片修补随机假字、错误箭头或虚构数字。
