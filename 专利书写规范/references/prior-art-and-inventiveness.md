# 专利查新、区别特征与创造性预审

## 1. 查新的目的

查新不是“找到几个标题相似的专利”，而是回答：

1. 独立权利要求的全部必要技术特征是否已被单一现有技术公开？
2. 若没有，真正的区别特征是什么？
3. 区别特征在本发明中产生什么技术效果？
4. 由该效果重新确定的实际技术问题是什么？
5. 现有技术是否给出了把区别特征用于解决该问题的技术启示？

检索结束必须能回到权利要求，而不是停在文献列表。

## 2. 检索前先拆发明

先形成发明概念表：

| 维度 | 内容 |
| --- | --- |
| 技术对象 | 影像、序列、组学矩阵、设备、模型等 |
| 数据来源 | DICOM、FASTQ、BAM、VCF、RNA-seq、实验室指标等 |
| 关键处理 | 分割、配准、图构建、特征选择、融合、校准等 |
| 核心约束 | 特定拓扑、损失、阈值机制、时序关系等 |
| 输出 | 掩膜、候选区、样本表示、概率、聚类等 |
| 技术效果 | 准确性、鲁棒性、计算量、内存、假阳性等 |

从中生成 2–8 个“语义块”，不要只把发明名称当检索式。

## 3. 四轮检索

### Round A：对象 + 核心技术

找同领域、同处理目标的专利。

例：
- 多组学 + 相似网络融合 + 癌症亚型
- CT + 肺结节 + 3D CNN + 假阳性
- 变异检测 + 测序数据 + 误差校正

### Round B：核心区别机制

不带疾病名，搜索真正的算法机制。

例：
- graph representation + multi-omics + topology constraint
- missing modality + fusion + imputation
- uncertainty + dual threshold + abstention

这一轮常能发现跨领域但技术更接近的现有技术。

### Round C：逐特征组合

用独立权利要求的步骤组合检索，看是否有单一文件完整覆盖。

### Round D：引用链与同族

对最接近专利继续看：

- 引用的专利；
- 审查员引用文献；
- 同族；
- 申请人同系列专利；
- 后续改进专利。

## 4. 数据源优先级

### 第一层：CNIPA 官方来源

用于法律、审查规则、公布公告和当前流程核查。

### 第二层：中国专利全文公开源

用公开说明书、权利要求、引用关系进行技术比对。法律状态须尽量交叉核验。

### 第三层：WIPO / EPO / Google Patents

适合全文、同族、引用和跨国检索。第三方显示的“Active/Granted”等状态不能替代法律结论。

### 第四层：论文、标准、代码

创造性评估中的现有技术不限于专利。公开论文、标准、产品文档、开源代码都可能构成重要技术背景，但必须记录公开时间和可核来源。

## 5. 检索记录必须可复核

每轮记录：

| 日期 | 数据库 | 检索式/语义块 | 过滤条件 | 命中 | 精读文献 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |

不要只写“已检索未发现相同专利”。没有检索式就不能复核。

## 6. 最接近现有技术怎么选

不要仅按标题或关键词相似度。

优先考虑：

- 技术领域相同或相近；
- 技术目的/问题相同或相近；
- 公开的必要技术特征最多；
- 与发明的结构和数据流最接近；
- 只需最少结构性改变即可到达本发明。

对医疗 AI，某个非医疗算法专利也可能比同疾病的普通分类专利更接近核心技术机制。

## 7. Claim chart

对候选独立权利要求逐特征建立：

| 特征ID | 当前拟保护技术特征 | D1 | D2 | D3 | 证据位置 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |

状态：

- E：明确公开；
- I：隐含但需论证；
- N：未见公开；
- U：无法核实。

新颖性审查重点看单一文件能否公开全部技术特征。不要把多个文件拼在一起声称“没有新颖性”。

## 8. 创造性三步法前置写作

### 第一步：最接近现有技术 D1

用 3–6 句话准确还原 D1 的技术方案和效果。

### 第二步：区别特征与实际技术问题

对每个区别特征写：

区别特征  
→ 在本发明中产生的技术效果  
→ 基于该技术效果确定实际解决的技术问题

禁止：

“区别是引入图神经网络，因此技术问题是如何引入图神经网络。”

应改为：

“区别特征通过保持基因网络拓扑关系降低跨组学融合过程中的无关边传播，因此实际技术问题是如何减少……”。

### 第三步：技术启示

检查：

- D1 本身是否提示该改进；
- D2/D3 是否用于解决同一问题；
- 两者组合是否需要创造性劳动；
- 所谓“公知常识”是否有可靠证据；
- 场景约束是否使常规算法需要结构性改造。

## 9. AI/算法案件的特殊创造性问题

### 9.1 不要把“应用到医学”当核心创新

若现有模型已执行同类识别，只是把训练对象换成癌症、肺结节或某种组学数据，且没有模型结构、训练方式、表示或输入关系的实质调整，创造性风险高。

### 9.2 技术贡献应写进权利要求

真正带来效果的：

- 特定输入表示；
- 模型结构；
- 模块连接；
- 损失；
- 约束；
- 采样；
- 数据流；
- 硬件/资源协同；

如果只存在于说明书，不进入权利要求，创造性评价中可能无法发挥作用。

### 9.3 计算机内部性能也可能是技术效果

如果算法与计算机系统结构存在特定技术关联，并改善内存、速度、存储、网络传输、并行效率等内部性能，应把这种关联写清楚。

## 10. 医学/生物信息学的检索关键词树

不要只搜疾病名。建议建立：

### 数据层
DICOM / WSI / FASTQ / BAM / VCF / gene expression / methylation / proteomics / metabolomics / laboratory data

### 处理层
segmentation / registration / variant calling / normalization / batch correction / feature selection / similarity network / graph / embedding / multimodal fusion

### 模型层
CNN / Transformer / GNN / autoencoder / survival model / causal feature / calibration / abstention

### 技术效果层
false positive / robustness / missing modality / batch effect / computational efficiency / memory / latency / interpretability

中文、英文、同义词、缩写都要覆盖。

## 11. 开源工具给本 skill 的启发

### Zaoqu-Liu/cn-patent

MIT 许可。值得吸收的流程思想：

- CNIPA-first；
- 先专利点挖掘，再查新，再写交底；
- 技术问题—技术方案—技术效果闭环；
- 质量门禁；
- 版本化迭代。

本 skill 不复制其具体提示词或代码，只融合高层方法，并进一步增加医疗、生物信息学、完整申请文件和证据台账。

### patsnap/mcp

Apache-2.0。其公开 MCP 目录展示了：

- 语义/相似度/关键词组合检索；
- novelty/FTO；
- patent family/legal status；
- 技术问题—方案—效果挖掘；
- life-sciences 数据源联动。

本 skill 将“多通道检索 + 结构化 patent mining”作为检索原则，但不依赖 Patsnap 付费数据，也不复制实现。

### rbouadjenek/patent-search

该公开研究项目基于 Lucene 做 prior-art search，并关联 SIGIR/ICAIL 关于术语选择与 query reformulation 的研究。其启发是：查新不能依赖单一原始查询，应根据初始命中持续重写查询并扩展术语。

### ClaimCheck

公开项目的核心工作流是把申请草稿与 invention disclosure/supporting context 对照，定位 claim-support、清楚性和一致性风险。本 skill 将“claim-support matrix”作为强制产物。

这些开源项目均不是中国专利法律权威。

## 12. 停止规则

出现以下情形应暂停“直接写完整本子”：

- 单一现有技术已经覆盖独立权利要求全部核心特征；
- 所谓区别只剩疾病/数据对象变化；
- 区别特征没有可解释技术效果；
- 技术效果只有未验证的口头主张；
- 发明事实不足以让本领域技术人员实施；
- 医疗客体风险无法通过真实技术方案澄清；
- 用户要求虚构实验数据来“补充分公开”。

此时输出 HOLD/STOP 原因和最小补充证据，而不是继续堆文字。
