# 官网申请字段模式与填报口径

本文件吸收 Fokkyp/SoftwareCopyright-Skill 对申请字段顺序、长度和来源口径的整理，并结合 2026-10 实际登记页面核对。它是“填报辅助 schema”，不是永久不变的法规文本；官网字段或限制变化时，以当前中国版权保护中心登记系统为准。

## 1. 当前常见字段顺序

| # | 字段 | 常见限制/枚举 | 来源 |
| --- | --- | --- | --- |
| 1 | 软件全称 | 必填 | 用户确认 + 项目证据 |
| 2 | 软件简称 | 可选，必须真正比全称简短 | 用户确认 |
| 3 | 版本号 | 如 V1.0 | 用户确认 |
| 4 | 软件分类 | 应用软件/嵌入式软件/中间件/操作系统等 | 软件事实 |
| 5 | 开发完成日期 | YYYY-MM-DD | 用户确认 + 证据 |
| 6 | 开发方式 | 独立/合作/委托/下达任务等，以当前页面枚举为准 | 权属事实 |
| 7 | 软件说明 | 原创/修改等 | 软件事实 |
| 8 | 发表状态 | 已发表/未发表 | 用户确认 |
| 9 | 首次发表日期 | 已发表时填写 | 用户确认 |
| 10 | 著作权人 | 主体类型、姓名/名称、证件等 | 用户确认 |
| 11 | 权利范围 | 全部/部分 | 权属事实 |
| 12 | 权利取得方式 | 原始/继受 | 权属事实 |
| 13 | 开发的硬件环境 | 通常 ≤50 字符 | 实际开发环境 |
| 14 | 运行的硬件环境 | 通常 ≤50 字符 | 实际/合理最低环境 |
| 15 | 开发该软件的操作系统 | 通常 ≤50 字符 | 实际开发环境 |
| 16 | 软件开发环境/开发工具 | 通常 ≤50 字符 | 实际工具 |
| 17 | 运行平台/操作系统 | 通常 ≤50 字符 | 实际运行环境 |
| 18 | 软件运行支撑环境/支持软件 | 通常 ≤50 字符 | 真实依赖 |
| 19 | 编程语言 | 预设选择 + 自定义 | 源码统计 |
| 20 | 源程序量 | 纯数字，全部第一方登记软件源程序总行数 | 可复算 |
| 21 | 开发目的 | 通常 ≤50 字符 | 业务理解 |
| 22 | 面向领域/行业 | 通常 ≤50 字符 | 业务理解 |
| 23 | 软件的主要功能 | 当前页面常见 500–1300 字 | 项目事实 |
| 24 | 软件的技术特点 | 标签 + 短文本，当前页面常见 ≤100 字 | 项目事实 |
| 25 | 代码鉴别材料页数 | 实际上传页数 | 最终 PDF/Word |

## 2. 关键填报规则

### 软件简称
没有必要可以留空。若填写，应是全称的真正简化表达，不要因为英文字符串反而比中文全称更长。

### 源程序量
是“登记软件全部第一方源程序总行数”，不是“被抽取进鉴别材料的行数”。

必须写清统计口径并排除：
- 第三方依赖；
- vendored 外部代码；
- venv/node_modules；
- build/dist；
- 自动生成代码；
- 文档；
- 测试是否计入需按软件主体口径审慎处理，默认不把测试作为核心登记源程序量。

### 代码材料页数
填实际最终上传材料页数。若程序不足 60 页而全部提交，就填全部实际页数。

### 开发环境/开发工具
不要把框架名当 IDE。优先采用：
`开发环境: Windows 11/开发工具: Visual Studio Code`
这类可核格式；实际没有 IDE 时不要硬填。

### 主要功能
500–1300 字时，应完整覆盖：
- 软件用途；
- 输入；
- 核心处理；
- 主要功能模块；
- 输出；
- 用户使用方式；
- 软件边界。

不得为了字数加入不存在功能。

### 技术特点
标签只是分类辅助。科研/生信软件并不因为使用算法就自动属于“人工智能软件”。标签应按实际性质选择；不符合时可以不选。

## 3. 字段来源等级

- AUTO_VERIFIABLE：语言、部分依赖、源程序量、代码材料页数；
- INFER_WITH_CONFIRMATION：软件分类、开发目的、行业、主要功能、技术特点；
- APPLICANT_CONFIRMATION_REQUIRED：软件全称、简称、版本、著作权人、完成日期、发表状态、开发方式、权利取得方式；
- FORMAL_DOCUMENT_REQUIRED：继受取得、委托/合作/任务开发等需要合同/任务书支持的情形。

## 4. 一致性门禁

正式提交前至少比较：

`申请表字段 ↔ 说明书封面/正文 ↔ 源程序页眉 ↔ 实际软件/版本 ↔ 截图`

名称、版本、著作权人、完成日期和功能出现实质冲突时，禁止 GO。

## 5. 官网变化处理

每次正式申请前：
1. 记录系统核验日期；
2. 截取/记录当前字段顺序和字符限制；
3. 若本文件与官网不同，优先官网；
4. 更新本文件并在 change log 记录。
