# Word三线表制作与渲染验收

用于已识别的数据表；不要把版式定位表、公式容器或嵌套表批量改成三线表。用户和已核实的期刊模板优先，以下线宽是内部默认。

## 1. 先锁定表格结构

保留原件，记录表号、位置、行列数、合并关系、实际表头行数、列宽、分节方向和现有跨页行为。表头可以占多行，不能默认所有表只有一行表头。核对脚注标记、单位、上下标、斜体、置信区间与统计符号；不改数字、有效位数或引用来改善外观。遇到修订、内容控件或特殊域，先确认工具能保留结构，再进行定点修改。

## 2. 设置三类横线

| 位置 | 默认线宽 | 边界判定 |
| --- | --- | --- |
| 表顶 | 1 pt | 第一物理行的上边界，覆盖整表宽度 |
| 表头下 | 0.5 pt | 最后一行表头的下边界，位于整个表头块之后 |
| 表底 | 1 pt | 最后一行数据的下边界 |

清除表级、单元格级和行级例外中的残余竖线、内部横线、对角线与装饰底色，取消单元格间距造成的双线。Word编辑界面的非打印网格线不等于实际边框，以输出页面为准。已有条件表格样式可能覆盖效果，必须在实际渲染中确认。必要的分组辅助线按明确要求单独处理，记录为例外。

水平合并和表头块内部的纵向合并均保留；表头下横线仍应落在最后一行表头。不要使用逻辑 `row.cells` 的合并别名把横线误加到纵向合并的起始行。跨越表头与数据边界的纵向合并不能机械设置重复表头，先人工确定合理结构，不擅自拆合并或复制数据。

## 3. 使用辅助函数

从本skill的 `scripts/word_format_helpers.py` 导入，定位已确认的表，再调用：

```python
from word_format_helpers import three_line_table

table = doc.tables[verified_table_index]
three_line_table(table, header_rows=verified_header_rows,
                 outer_pt=1.0, header_pt=0.5,
                 line_spacing=1.0, padding_pt=2.0)
doc.save(output_docx)
```

该函数保留文字、合并结构与水平对齐；按物理单元格设置边框、重复表头和正常行不拆分，取消精确固定行高及单元格段落的“与下段同页”。它不会自动确定列宽、设置表题表注、更新域、改变页方向或完成视觉验收。嵌套表、缺省网格单元格、跨表头边界的纵向合并在修改前报错，转人工处理；不要通过忽略异常假装格式已完成。使用python-docx当前安装版本实际运行，尤其复核依赖底层XML的合并处理。

## 4. 处理宽度、分页与说明

- 按本节页面可用宽度分配列宽，长变量名和区间预留空间。叙述列左对齐，数字列按要求右对齐或小数点对齐；不把每个单元格强制两端对齐，不改变数值小数位。避免靠极小字号或固定行高挤入页面。
- 重复的是连续的完整表头块。长表自然跨页；只让表题与首行保持连接，不将所有数据行串联成“与下段同页”。正常高度的数据行不拆分；单行高于一页时单独判断是否允许拆分，不一律禁拆造成溢出。
- 跨页后的重复表头可能重复表顶和表头下横线，渲染器也可能在分页边界重复外框底线。这仍是三类边框，不能要求整份多页文档只能出现三条物理横线。按期刊要求核查分页边框，不给每个页末人为添加数据行或底线来模拟分页。检查连续页是否有表头、数据是否接续、有无空白页或过大空白。
- 表题保留编号与文字，连接表格起始位置；表注放在最后一行之后，尽量与表尾同页。长表注确需延续时保持归属清楚，不隐藏、删除或缩写注释来缩短页面。

## 5. 渲染闭环：每次验收针对最新文件

1. 先对照原件核验文字、数字、合并、域/链接、修订与批注。结构检查可发现错误，但不能认证三线表实际显示正常。
2. 检查字体是否安装且覆盖文中字符。字体替代须说明；PDF能提取文本不能证明页面没有缺字。
3. 使用环境提供的documents技能定位其 `render_docx.py`，以新输出目录渲染最新DOCX。示例中的变量由实际环境提供，不依赖固定机器路径：

   ```bash
   python "$DOCUMENT_RENDERER" "$INPUT_DOCX" --output_dir "$QA_DIR" --emit_pdf
   ```

   没有该脚本时可使用可用的Word/LibreOffice导出PDF再生成页面图片，并记录渲染器。保留原DOCX，不在导出副本中接受修订或删域。不要把不同修改版本的图片混在同一验收目录。
4. 逐页打开全部页面图片。边框很细时放大表格局部；缩略图或文本提取只供定位，不代替逐页验收。
5. 逐表核查整宽顶线、表头分隔线、最终底线；多层表头没有误加中间横线；无竖线、对角线、双线和残余底色。核查列宽、换行、数字对齐、上下标、缺字、裁切、重复表头、数据接续、表题与表注位置。
6. 有缺陷就修正DOCX并重新渲染全部受影响页面；最终交付前查看最新文件的所有页。未经实际渲染或尚有未看页面时，F20不能标为通过。

## 6. 诊断与验收记录

| 表现 | 优先检查 | 修正后必须确认 |
| --- | --- | --- |
| 表头中间多一条线 | 表头行数、纵向合并别名、条件样式 | 分隔线位于完整表头块之后 |
| 竖线、双线仍存在 | 单元格边框、行级例外、单元格间距 | 页面上没有残余线，非打印网格不计 |
| 整表移到下一页或大量留白 | 单元格段落keep-next、行高、过长行 | 长表能自然分页，首尾说明关系清楚 |
| 字被切掉或数字挤成多行 | 精确行高、列宽、字号与内边距 | 所有内容可读，数字文本保持原样 |
| 续页没有完整表头 | 连续表头标记、跨边界合并、渲染器 | 每个续页显示完整表头，数据不重复不遗漏 |

填写F09—F13及F18—F20：表号/页码、观察到的问题、规则来源、修改动作、最新渲染结果和未解决例外。区分“结构通过”与“视觉通过”；不总分认证。渲染失败时记录错误与完成范围，不把已设置XML边框写成视觉通过。默认只交付请求的格式副本和自查结果，QA图片与合成测试稿不混入投稿文件或公开skill仓库。
