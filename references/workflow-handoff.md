# 模块交接与版本状态

## 最小交接

交接只带下游所需材料。记录：任务ID与授权范围；输入和输出的稳定ID/版本；对应主张和证据；所用目标量、独立单位、方法与运行身份（适用时）；实际完成的核查及开放项；下游可以做的动作和完成条件。重复问题用同一问题ID并列模块检查ID，避免凑清单总数。不同模块都可能有L01等编号，引用时带模块name。

轻量任务可用短表或文字；不强制JSON、数据库或专用调度工具。不要把台账、内部P级问题和调试日志塞进论文或附信读者版。

## 分开的状态

| 维度 | 内部值 | 含义 |
|---|---|---|
| 执行 | pending / running / completed / blocked / not_applicable | 是否完成所要求的动作；completed不表示结论正确 |
| 核验 | unassessed / partial / verified / failed / not_applicable | 针对写明的检查范围的实际状态；verified不等于全研究认证 |
| 新鲜度 | current / stale / unknown | 所用输入/版本是否仍对应当前任务；current不等于科学有效 |

检查范围分别写科学主张、数值、技术、视觉、引用、期刊要求等；可以“文件已生成，但视觉未核验”。上述值仅供流程交接，**不重命名**模块原有的通过/部分通过/无法核实或RoB/GRADE领域判断，更不能把不同P0含义硬等同。

## 变更传播

用`artifact_id → depends_on`记录必要依赖，来源可为材料、分析、主张或外部规范。原数据保留；修订用新版本，旧输出保存为旧版。关键输入改变后：

1. 定位直接使用该输入或结果的成果；
2. 将这些成果与其相关核验标stale，沿已知依赖继续追踪；
3. 按授权重算/重写/重画/重渲染，核查后将**实际重核的范围**恢复current；
4. 未授权改动的关联材料只列待同步，不静默改写。
5. 交付时逐项列出“变更源｜受影响成果/新鲜度｜须在更新后重做的检查/实际状态｜未受影响工作/依据”。没有受影响或未受影响项目时也明确写“无”及原因。

例：估计方法或样本纳排改变，影响分析数值、Results、图表、补充和附信中的结果主张；仅修附信礼貌用语通常不使源分析失效。未提供的图不猜已重画。内容相同不必重做与变更无关的检查，但指南/期刊等时效性依据仍需核实是否发生相关更新。

“需同步”只描述动作，不能证明核验完成。重写Results后，要在该新版文本上核对数值、方向、版本和主张强度；重画图后再做导出与视觉QA；更新补充后再查正文/表图/交叉引用一致性。明确标出已经实际完成、生成后才能执行和无需重做的检查。不得因一个依赖变更把致谢、纯格式等无依赖工作一并作废，也不得用“其他工作可继续”代替具体成果与依据。

## 接续与终点

从实际未完成事项接续，先核当前材料，不能拿会话记忆替代文件。每个blocked项写原因、最小解除条件和可独立继续事项。术语“投稿终版”只能用于明确范围内必要检查已经完成的文件；未核状态或未知作者声明保留工作稿边界。多个模块completed不能自动汇总为“研究有效/可录用”。
