# 陌生问题的最小研究协议

这是内部工作流程，不是经验证的科学质量量表。对确实影响当前任务的缺口使用；不要把常规编辑变成全面研究。

1. **写清待决定事项。** 把“不懂这个方法”改成一个具体问题：这个方法能否估计当前目标量？这个字段代表什么？这个失败来自输入还是环境？标知识、证据、数据、实现或权限缺口，指出结论依赖它的哪个部分。
2. **列出可区分解释。** 给出必要的竞争解释，以及最便宜的区别检查。比如数值不一致先查版本、分母、单位、预处理和算法；不得预设作者有错或新方法一定优越。没有多个解释时不强行凑数量。
3. **按问题找来源。** 医学主张查相应原始研究/正式指南；方法假设查原方法与权威章节；接口和格式查对应版本的官方说明/代码；法律规则查现行官方文件。GitHub skill、论坛和模型总结用于发现线索或工程经验，随后核实承担结论的来源。准确概念、同义词、错误原文、版本和反证可分别检索；改换一个检索概念应有目的，不能机械重复。
4. **读到能支持判断的位置。** 记录来源身份、版本/日期、章节/表/代码行和实际读取范围；区分明确规则、经验、推断和仍未确认事项。摘要/搜索片段不等于读过实现；草案和更新计划不等于正式发布版本。冲突时比较对象、目标、时间窗口和版本，保留未解决项。
5. **先做最小验证。** 仅在授权范围内，用不泄露真实材料的合成输入或项目获授权小样本核查关键假设。保存输入、代码、命令和实际输出；正常输入、最关键边界与必要负例用于暴露假设，不照着实现写一组永远通过的断言。静态审查不能替代运行，运行成功不能替代统计/语义有效性。没有可运行环境时明确交未执行方案。
6. **给可解除的裁决。** 写“哪些解释被排除、什么仍未知、当前允许哪种表述、下一个动作为什么会改变判断”。来源不可读、数据不识别目标量、关键验证失败或预算已耗尽时，换一条有依据的路径、缩小任务或停止该项推断；保留失败原因与继续所需材料。不能无限修工具来维持预设选题。

先确定检索和试验的合理范围；连续失败且没有新信息时停止同一路径。不要为填满模板而编造命中数、调用成本、重算结果或完整阅读状态。无法互动时采用可逆的最小假设，显式保留会改变结论的未知，不擅自替作者作实质决定。

只有在实际来源和验证支持后，将解决方法写成可复用步骤：适用情境、前置条件、来源/版本、操作、失败信号、补救、边界及何时重新核查。概括机制而不是记住某一个病例的答案；一例成功不等于跨任务可靠。
