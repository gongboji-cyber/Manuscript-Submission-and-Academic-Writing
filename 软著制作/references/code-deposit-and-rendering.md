# 普通交存源程序材料制作规范

1. **冻结边界**：确认软件名称/版本/commit/SHA-256，甄别原创代码、合法修改代码及第三方依赖。人工列出需要交存的源文件实际路径及合理顺序，排除编译产物、vendor、lockfile、模型、二进制、病历和凭据。
2. **真实连续**：文件内部不得删行、重排行或生成新代码；跨文件拼接保留明确的路径、原始行号和边界，在权利人确认程序完整性之前不能声称所选子集就是整个软件。
3. **预排版**：根据官方登记办法第十条，普通源程序前后各30页，整体不足60页交全部，除特定情况外每页程序不少于50行。脚本可按50原始行构成一逻辑页：>3000行取头1500+尾1500；<=3000行取全部。逻辑页和真正PDF页可能不同，最终须实际渲染。
4. **工具**：在保密的本地工作站运行（先确认文件版权归属）：
    python "软著制作/scripts/extract_code_evidence.py" --project "/private/software" --out "/private/deposit" --files src/main.py src/engine.py
   脚本仅以显式文件组成普通交存材料，生成manifest.json和按逻辑页输出的纯文本；不会自动生成可直接提交的PDF。脚本拒绝写入项目树内，避免误上传GitHub。
5. **DOCX/PDF**：用A4、可辨认等宽代码、连续页码，页眉页脚不算程序50行；保持原始代码字符、缩进和次序。逐页检查长行换行、乱码、代码丢失、代码行数、首尾连续、页数与分页，报告实测PDF总页数及每页情况。
6. **特殊交存**：需机密遮盖或另选连续页面按第十二条另行审议，不在脚本普通材料上随意删段/打码。
7. **禁止灌水**：不得靠AI输出、重复函数、无意义注释来凑行、凑页；不能混淆整体代码总量与所选真实自研代码量。

脚本行溯源、页内空行、短尾页、过长代码行及正式版“是否达到每页不少于50行”均须人工和PDF验收。没有渲染条件时只能HOLD。
