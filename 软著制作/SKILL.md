# 软著制作：从真实项目到可审计的登记材料

## 目标、边界和资源

本 Skill 与“专利书写规范”平级，保护对象是**真实软件程序及相关文档的具体表达**。软著登记不等于发明专利，不赋予算法思想、数学方法或临床疗效保护；登记证书也不是无争议权属的最终裁判。

## 四道 P0 门禁

1. **真实软件**：没有真实、可固定版本的源程序，只能做需求或开发规划，不能交付“可提交软著成品”。不为凑3000行虚构代码、注释或复杂模块。
2. **权属**：不得自动假定源码作者、GitHub所有者、科研论文作者、学生本人或课题负责人是唯一权利人。合作、职务、学校/医院、委托、任务、受让、原软件修改等先核实合同及许可。
3. **真实性**：不得编造软件功能、运行截图、测试、发表日期、源程序量、开发环境和医疗AI性能。图示必须区别“设计示意图”和实际截图。
4. **保密**：公开Skill仓库只保留通用规则与合成样例。用户源代码、证件、合同、患者数据、机构内部系统和密钥必须在私有工作目录处理。

## 阶段0：识别任务

- 从零：先做软件真实性和可登记性预审；不将论文/模型构想包装成已完成软件。
- 现有软件：执行完整登记材料工作流。
- 科研代码集合：识别真实软件边界和入口，不把第三方模型+零散脚本冒充完整原创平台。
- 补正：逐字核对补正通知并修复对应原始证据，不随意换名、换版权人或换软件版本。
- 升级/衍生：追溯旧版权属、许可和确实增加的程序表达。

## 阶段1：证据冻结

建立事实台账：软件全称/简称/版本；项目根目录与Git commit或归档SHA256；真实入口、主要功能、软件架构、开发语言、安装和运行环境、依赖/许可证；软件完成日期、首次发表或未发表；权利人、开发方式、权利取得方式、协议/证明；安全敏感资料及截图可公开范围。

使用 VERIFIED（文件及实际运行可核）、DECLARED（仅申报人陈述）、UNKNOWN（缺失）、CONFLICT（冲突）标识。关键项仅DECLARED/UNKNOWN时不得GO；针对学院/医院/委托项目先进行著作权合同审计。逐项清点第三方库、预训练模型与许可证，不能将他人成果视为自研。

## 阶段2：普通交存程序材料

根据《计算机软件著作权登记办法》第十条，一般为程序与任何一种文档**分别**前、后各连续30页；不足60页时提交全部；除特定情况外程序每页不少于50行，文档每页不少于30行。不能把这理解成必须人为扩写到60页。

1. 核定本次软件的真实原创/已获许可源文件范围，明确列表及顺序、程序边界，不包括vendor、外部SDK、编译产物、密钥、患者数据。
2. 在私有目录运行 scripts/extract_code_evidence.py，从显式文件顺序形成带SHA256、原文件行号的抽取清单。默认每50原始行作为**逻辑预排版页**，不代替实际PDF页数。多文件拼接、原始程序完整性须人工核实。
3. 输出普通交存源程序TXT和manifest，再制作A4 DOCX/PDF。确保真实行顺序不变，页眉页码不算源代码，不能把过长行的视觉换行算多条源代码。
4. 逐页实测程序PDF的行数、总页数、起止段连续、乱码、缩进、代码被裁剪或分页变化；脚本本身不能认证最终合规。
5. 若要机密遮盖、例外交存，必须单独依据登记办法第十二条选择和确认，不在普通交存后随意涂黑/挑选非连续片段。

## 阶段3：文档与运行证据

选择符合软件真实形态的文档：GUI写真实使用手册与运行截图；CLI写安装、参数、输入格式、输出目录、异常和可复现命令；API/库写方法签名、配置、架构和真实调用示例。每条功能须有代码路径/运行记录/截图证据，示意图注明“示意”不冒充界面。医疗AI不得把风险分数写成临床确诊，不添加未经证实的训练数据与有效性。按适用的前后页及文档30行规则逐页渲染审核。

## 阶段4：申报信息与证明文件

从事实台账生成申请字段草稿：软件全称、简称、版本、申请主体、完成/发表、开发方式与权利取得、开发及运行环境、语言、源程序量、用途和技术特点。实际字段、文件格式、账号、上传步骤与办理方式必须以**当次中国版权保护中心官网及表单**为准。缺值标【待确认】，不猜身份证明、单位或真实日期。根据独立、合作、委托、职务、许可或转让情形输出证明清单。

## 阶段5：三向审计与交付裁决

- 源码 ↔ 实有功能/运行结果：主要功能都可追溯代码和实测。
- 源码 ↔ 用户文档：软件名/版本/入口/参数/页面/环境/输出一致。
- 代码+文档 ↔ 登记字段+权属：著作权人、软件量、语言、发表日期、版本一致。

按 references/checklist.md 逐项记录PASS/PARTIAL/FAIL/NA/UNKNOWN、证据ID、修正及复核。裁决只用 STOP_INELIGIBLE_OR_RIGHTS_CONFLICT、HOLD_EVIDENCE、GO_TO_HUMAN_REVIEW；后者只代表提交申请人和登记机构复核的准备状态，不承诺受理或获证。

## 遇到陌生情况的解决办法

先识别法律、平台、权利、源码还是文档问题；优先检索现行《计算机软件保护条例》《计算机软件著作权登记办法》与版权保护中心现行办事指引；技术疑问查源码/Git/依赖官方文档/真实测试，再参考GitHub。记录官方来源、核实日期、条文和是否适用于本案；无法在线核实时标UNVERIFIED，不能使用论坛旧教程冒充官方要求。
